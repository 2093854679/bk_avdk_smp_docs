# 睡眠模式说明

睡眠模式是系统低功耗运行的一种模式，对应代码中的 `PM_MODE_LOW_VOLTAGE`。在该模式下，系统保留必要的AON和唤醒逻辑，其余不需要工作的模块进入低功耗或关闭状态。

Wi-Fi和BLE的保活场景也属于睡眠模式。进入该模式后，AP侧和CP侧CPU都可以下电，系统依靠RTC、Wi-Fi/BLE协议周期或者其他配置的唤醒源周期性唤醒，完成与服务器、手机或网关的通信后，再重新进入睡眠模式。

<a id="id2"></a>

## 典型应用场景

> - Wi-Fi保活：设备按照DTIM或listen interval周期唤醒，接收AP缓存数据，必要时与服务器通信。
> - BLE保活：设备按照BLE连接间隔或业务配置周期唤醒，处理BLE事件，必要时通过手机或网关与服务器通信。
> - RTC/GPIO/Touch唤醒：设备大部分时间处于睡眠模式，RTC定时、GPIO电平/边沿或Touch事件触发后退出睡眠，处理业务后再进入睡眠模式。

<a id="id3"></a>

## 进入睡眠模式的基本条件

> - RTOS没有任务需要处理，系统进入IDLE任务。
> - 满足 `PM_ENTER_LOW_VOL_MODULES_CONFIG` 中配置的睡眠投票。应用层通常需要关注 `PM_SLEEP_MODULE_NAME_APP` 票，业务处理完成并允许睡眠时投上该票。
> - 不需要工作的外设、音频、视频、LCD、CPU1/CPU2等模块已经关闭或进入可睡眠状态。

<a id="id4"></a>

## 睡眠模式保活流程框图

```
+-----------------------------+
|      业务处理完成            |
|  关闭不需要的外设/业务模块    |
+--------------+--------------+
               |
               v
+-----------------------------+
|      配置唤醒源              |
| RTC / GPIO / Touch / Wi-Fi  |
| BLE协议周期或业务定时         |
+--------------+--------------+
               |
               v
+-----------------------------+
|      投睡眠票                |
| PM_SLEEP_MODULE_NAME_APP    |
+--------------+--------------+
               |
               v
+-----------------------------+
|        进入睡眠模式          |
| AP侧CPU下电，CP侧CPU下电     |
| 保留AON/32K/唤醒逻辑         |
+--------------+--------------+
               |
               v
+-----------------------------+
|      周期性或事件唤醒        |
| RTC / Wi-Fi / BLE / GPIO    |
+--------------+--------------+
               |
               v
+-----------------------------+
|      恢复必要模块           |
|  处理网络、BLE或本地事件     |
+--------------+--------------+
               |
               v
+-----------------------------+
|   与服务器/手机/网关通信      |
|  同步状态、收发保活数据       |
+--------------+--------------+
               |
               v
+-----------------------------+
|      业务处理完成后          |
|      再次进入睡眠模式         |
+-----------------------------+
```

备注

睡眠模式不会像deep sleep一样在唤醒后复位系统。睡眠唤醒后，系统会恢复必要上下文并继续运行，因此进入睡眠前需要确保业务模块的关闭、投票和恢复流程是成对的。
